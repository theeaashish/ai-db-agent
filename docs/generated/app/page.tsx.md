# `app/page.tsx`

The `app/page.tsx` file serves as the primary user interface for the **AI DB Agent**. It provides a conversational chat experience that allows users to interact with their database using natural language, including querying data and generating structured reports.

## Overview
This component is a client-side React application that leverages the `@ai-sdk/react` library to manage chat state and streaming responses. It integrates seamlessly with the backend API defined in `app/api/chat/route.ts`.

## Key Features
*   **Natural Language Querying:** Users can ask questions about database content (e.g., "Show me all products with low stock").
*   **Tool Integration:** The UI dynamically renders results from specific AI tools:
    *   **`db` tool:** Displays raw database query results in a formatted, scrollable code block.
    *   **`generate_report` tool:** Renders a specialized `DocumentPreview` component for structured data reports.
*   **Interactive Chat Interface:** Features a modern, dark-themed UI with auto-scrolling, loading states, and suggested prompt buttons for quick interaction.
*   **Responsive Design:** Built with Tailwind CSS, featuring a glassmorphism aesthetic, dynamic background animations, and a sticky input area.

## Components & Hooks
*   **`useChat`**: A hook from `@ai-sdk/react` that manages the message history, streaming state, and the `sendMessage` function.
*   **`DocumentPreview`**: An imported component used to display reports generated by the AI.
*   **`messagesEndRef`**: A `useRef` hook used to ensure the chat view automatically scrolls to the latest message.

## How it Works
1.  **Initialization**: When the page loads, the user is presented with a welcome screen containing suggested queries.
2.  **Interaction**:
    *   The user submits a query via the input form.
    *   The `handleSubmit` function triggers `sendMessage`, which sends the request to the `/api/chat` endpoint.
3.  **Streaming**: The UI listens to the `status` of the `useChat` hook. While the agent is "thinking" or streaming, a loading indicator is displayed.
4.  **Rendering**:
    *   Messages are mapped and styled based on their role (`user` vs `assistant`).
    *   Tool invocations are handled conditionally:
        *   **`call` state**: Shows a "Thinking/Executing" spinner.
        *   **`result` state**: Renders the specific output (either a `DocumentPreview` or a JSON code block).
